Budetau — Feature List & Roadmap

Living catalogue for the local-first budget planner (Tauri v2 + Vue 3 + SQLite). Organised into three buckets: what's added, what we want for sure, and quality-of-life nice-to-haves. A short "not now" list keeps explicitly-parked ideas from getting lost.

SHIPPED built & verified IN PROGRESS being built now PLANNED committed, want for sure QoL nice-to-have NOT NOW parked

1 · What's added SHIPPED

Everything below builds, is wired to the real SQLite database, and is covered by tests (20 Rust unit tests) and a visual pass.

Foundation

FeatureDetail
Local-first core ✓Tauri v2 + Vue 3 + TS, single cloud-syncable SQLite file, WAL disabled (no -wal/-shm sync conflicts).
Schema & migrations ✓5 tables, user_version migrations (now at v2), money as INTEGER cents, FKs on.
Atomic balances ✓Insert/update/delete adjust account balance(s) in one DB transaction; transfer-safe; never drifts.
Typed IPC bridge ✓13 Rust commands ↔ typed api.ts, camelCase via serde; Pinia stores with mutation actions.

App & everyday use

FeatureDetail
App shell ✓Native macOS title bar, sidebar nav, floating + button, ⌘K quick-add, responsive narrow icon rail.
Dark mode / theming ✓Light / dark / system; a real dark palette (not an inversion), persisted.
Dashboard ✓Hero (income / spend / net this month), budget cards with under→near→over spectrum, alert banners, first-run empty state, month navigator.
Transactions ✓Day-grouped cards (signed amounts, category colors), search + filters, edit & delete, no-results state.
Quick-Add modal ✓⌘K/FAB; amount, category autocomplete, date; expand for note/account/type; expense·income·transfer; success toast.
Budgets ✓Create a budget per category; default "Cash" account seeded so the first entry always works.
Settings ✓Live local DB path (with copy), theme toggle.

Backend just landed (this sprint)

FeatureDetail
Configurable alert threshold ✓budgets.alert_threshold column + commands.
Account update / delete ✓Rename/edit accounts; delete is refused if any transaction still references the account.
Budget update / delete ✓Edit amount/threshold and remove budgets.

Accounts · Analytics · Sub-categories SHIPPED

FeatureDetail
Accounts management ✓Settings: list / add / rename / delete accounts, with the delete-guard surfaced.
Category management ✓Settings: grouped list, create / rename / delete, assign parent & color.
Analytics & charts ✓ApexCharts cash-flow, spending donut (with parent→sub drill-down), month-over-month.
Configurable budget alerts ✓Per-budget "alert at X%"; Manage Budgets modal to edit/delete.
Sub-categories ✓One level (parent → sub); roll-up to the parent budget; across manager, quick-add, analytics drill-down, and transactions.
Amount-sign hardening ✓Amounts stored as positive magnitude (sign from type); backend abs-guards insert/update so balances can't be corrupted.
Backup & restore ✓Settings: export a verified timestamped copy or restore from a file (Tauri dialog plugin). integrity_check on both sides; restore confirms, auto-backs-up the current DB, migrates an older backup forward, then reloads.
Balance recompute utility ✓Settings → Maintenance: rebuild every accounts.balance from opening_balance + transaction history (migration v4 adds/backfills opening_balance). Safety net against incremental-balance drift.
Envelope budgeting — YNAB core loop (v1) ✓Zero-based budgeting: Ready to Assign → Assigned → Activity → Available with monthly rollover and move-money. Migration v5 (category_months) + engine; Plan screen (parents are read-only group headers); income → Ready to Assign; envelope Dashboard. Replaces the fixed-amount budgets model. v2 refinements (credit cards, off-budget accounts, cash-overspend→next-month RTA) deferred — see HANDOFF §7.
Recurring transactions ✓Scheduled/auto-repeating entries (rent, salary, a biweekly paycheck). Migration v6 (recurring_rules) + an on-launch scheduler that catches up any due/missed occurrences (idempotent); managed from a Settings card. Cadences: weekly / biweekly / monthly / yearly. Income rules post to Ready to Assign.

4 · Not now PARKED

Considered and intentionally parked — revisit when the core is solid or there's a real need.

FeatureWhy parked
Database encryption (SQLCipher)Adds build complexity + a passphrase UX; local file in a user-controlled folder is the current model.
Multi-currency + conversionAccounts store a currency, but cross-currency aggregation (rates) is significant scope.
Mobile (iOS/Android)Tauri supports it, but the cloud-folder sync model gets tricky on mobile sandboxes.
Auto-update + signing / notarizationNeeded for public distribution, not for local development.
Localization (i18n)Defer until the feature set stabilises.
