Budetau — Engineering Handoff & Continuation Plan

Read this first if you are a new agent or developer picking up the project. It captures the stack, the non-obvious conventions that will bite you, what's shipped, and how to continue. Sources of truth: the code (src/, src-tauri/) and the feature list.

State as of this handoff: branch phase-1-local-infra, HEAD fe435cd. 4 views, 18 Vue components, 6 Pinia stores, 18 Rust commands, 22 backend tests (all green). Build + lint + clippy clean.

1 · What this is

Budetau is a local-first personal budget planner — a native macOS desktop app. All data lives in a single private SQLite file in the user's Documents folder (cloud-syncable). No servers, no accounts.

LayerTech
ShellTauri v2
FrontendVue 3 (<script setup>) + TypeScript + Vite + Pinia + Vue Router + Tailwind v3 + ApexCharts
BackendRust + rusqlite (bundled SQLite), serde
DBSQLite single file at ~/Documents/BudgetPlanner/budget.db; WAL disabled for cloud-sync safety

2 · Quick start

Toolchain is NOT on the default PATH. Node (Homebrew) and Rust (rustup) are installed but not on a non-login shell's PATH. Prefix every toolchain command with:
export PATH="$HOME/.cargo/bin:/opt/homebrew/bin:$PATH"
# run the desktop app (recompiles Rust + serves Vite)
npm run tauri dev

# frontend gate
npm run build        # vue-tsc --noEmit && vite build  (strict: noUnusedLocals/Parameters)
npm run lint         # eslint . --fix

# backend gate
cd src-tauri && cargo test          # 22 tests
cd src-tauri && cargo clippy -- -D warnings

Network/build commands need sandbox escape in this environment (dangerouslyDisableSandbox). The DB auto-creates and migrates on first launch.

3 · Data model

Money is always stored as INTEGER cents. Schema version tracked via PRAGMA user_version; migrations are append-only in src-tauri/src/db.rs (migrate_v1..v3), each bumping the version independently.

TableKey columns
app_profilesid, profile_name, created_at, db_sync_path
accountsid, profile_id, name, balance (cents), currency, type
categoriesid, profile_id, name, color_code, type, parent_id (v3: NULL = top-level; one level of nesting)
budgetsid, profile_id, category_id, period, amount (cents), alert_threshold (v2: 0–1 fraction)
transactionsid, account_id, amount (cents, positive), category_id, date, note, type, transfer_account_id

Migrations: v1 core tables · v2 budgets.alert_threshold · v3 categories.parent_id. On a fresh DB, seeding adds a "Personal" profile, default categories (incl. example subs under Dining Out), and a default "Cash" account. Seeding is per-entity idempotent, so legacy DBs backfill a default account but do not get example sub-categories (by design).

4 · Conventions & invariants MUST READ

① Transaction amounts are a POSITIVE magnitude. The sign comes from type (expense subtracts, income adds, transfer moves between accounts). Never store a signed amount. The backend (insert_transaction / update_transaction_logic / adjust_balances) defensively .abs()es it. A signed amount inverts the dashboard net and corrupts balances — this was a real bug (fixed in fe435cd).
② Balances are mutated incrementally, not recomputed. Insert/update/delete adjust accounts.balance atomically inside one rusqlite transaction. This is fast but fragile: a bad write can drift a balance. Recommended next hardening: a "recalculate balances from transactions" maintenance command. There is no separate "opening balance" column — the account's starting balance is baked into balance at creation.
③ Prettier config is semi:false. NEVER write multi-statement inline template handlers like @click="a = 1; b = 2" — Prettier strips the semicolons and reformats into invalid code that breaks the Vue compiler. Always extract to a method and use @click="myMethod". This broke the build twice.
④ Budgets roll up. A budget attaches to a top-level category; spending in any of its sub-categories counts toward it. The frontend uses categoryStore.descendantIds(id) for this. Category helpers live in src/stores/category.ts: topLevel, childrenOf, descendantIds, parentOf, displayPath (→ "Dining Out › Coffee").

IPC contract

  • Rust structs use #[serde(rename_all = "camelCase")]; frontend types in src/types/index.ts mirror them.
  • All 18 commands return Result<T, String>; typed wrappers in src/api.ts; Pinia stores own mutations and re-fetch affected stores (e.g. transaction mutations refresh accounts).
  • Commands: get_db_path, list/create/update/delete for accounts, categories, budgets, transactions (delete guards: account/category in use is refused).

5 · How to verify UI changes

The app needs the Tauri runtime for real IPC, but you can drive the Vite dev server in a headless browser and mock window.__TAURI_INTERNALS__.invoke to render any data state. Pattern used throughout this project (preview tools):

// .claude/launch.json runs vite directly (node path, since npm isn't on PATH):
{ "name":"vite-dev","runtimeExecutable":"/opt/homebrew/bin/node",
  "runtimeArgs":["node_modules/vite/bin/vite.js","--port","1420"],"port":1420 }

// then in the page: define window.__TAURI_INTERNALS__.invoke = (cmd,args)=>Promise.resolve(mockData[cmd])
// navigate (click sidebar <a>) to remount views → they re-fetch with the mock.

ApexCharts has an entrance animation — screenshot after ~700ms. Always run the production build + lint after any lint --fix (Prettier can re-break inline handlers).

Recommended workflow (what worked here)

  1. Wave 0 (you/orchestrator): do all schema migration + Rust commands + api.ts/types/store changes in the shared files yourself, commit as a checkpoint. This avoids parallel agents colliding on db.rs/commands.rs/lib.rs.
  2. Wave 1 (parallel agents): one agent per UI surface, each owning a disjoint set of files (a view + its components). Give each agent: the toolchain PATH rule, the Prettier-handler rule, the store helpers it needs, and "no public interface changes."
  3. Wave 2 (you): run the full gate on the merged tree, fix leftovers, visual-verify with the mock-invoke pattern, commit.

8 · Known issues / gotchas

  • Balance drift (invariant ②) — no recompute utility yet. Top of the backlog.
  • ApexCharts bundle ~518 kB → one chunk-size build warning. Harmless for desktop; lazy-load the Analytics route to silence it.
  • "Current month" captured at mount in Dashboard/Analytics — won't auto-advance past midnight if left open. Pre-existing, minor.
  • Stray git worktree: an agent left one under .claude/worktrees/ (gitignored). eslint now ignores .claude/**; remove with git worktree remove if it bothers you.
  • Example sub-categories only seed on a brand-new DB; existing DBs get the parent_id column but no example data (create subs in Settings → Categories).
